# Персональные данные и безопасность

| ID | Требование |
|---|---|
| SEC-001 | Система должна применять least privilege, deny-by-default и separation of duties для привилегированных операций. |
| SEC-002 | Аутентификация должна поддерживать надежное хэширование паролей, MFA, rate limiting, безопасное восстановление и защиту от credential stuffing. |
| SEC-003 | Все tenant-данные должны иметь неизменяемый tenant_id; защита должна действовать на API, service и database слоях. |
| SEC-004 | Авторизация должна учитывать роль, ownership, ветку/глубину, назначение, purpose, поле и состояние объекта. |
| SEC-005 | Данные должны шифроваться при передаче и хранении; ключи и секреты хранятся отдельно, ротируются и не попадают в логи. |
| SEC-006 | Сессии должны иметь срок, ротацию refresh token, revoke, список устройств и завершение привилегированных сессий. |
| SEC-007 | Изменение ролей, структуры, заказов, согласий, интеграций, экспорты, break-glass и AI-решения должны журналироваться. |
| SEC-008 | AuditLog должен быть append-only, защищен от изменения обычными администраторами и иметь контролируемый retention. |
| SEC-009 | API должно проверять input schema, object-level authorization, rate limits, replay/signature webhooks и безопасный CORS/CSRF профиль. |
| SEC-010 | Файлы должны сканироваться, проверяться по типу/размеру, храниться с private access и выдаваться по короткоживущим ссылкам. |
| SEC-011 | Система должна вести Consent по purpose/channel/version/evidence и применять withdrawal без необоснованной задержки. |
| SEC-012 | Система должна поддерживать запрос доступа, исправления, экспорта, ограничения и удаления/анонимизации согласно jurisdiction profile. |
| SEC-013 | Retention должен задаваться по категории данных, tenant и юрисдикции; legal hold имеет приоритет над scheduled deletion. |
| SEC-014 | Экспорт и массовый доступ должны иметь отдельное право, лимиты, watermark/metadata при необходимости и аудит. |
| SEC-015 | Логи, метрики и traces не должны содержать токены, секреты, полный message body или необязательные PII. |
| SEC-016 | Резервные копии должны шифроваться, проверяться восстановлением и удаляться по согласованному жизненному циклу. |
| SEC-017 | Должны существовать vulnerability management, dependency scanning, SAST/DAST, penetration testing и incident response. |
| SEC-018 | Break-glass доступ должен требовать обоснование, MFA, срок, одобрение по политике и последующий review. |
| SEC-019 | Интеграции используют OAuth2/OIDC/API keys/mTLS по возможностям; scopes минимальны, credentials ротируются. |
| SEC-020 | AI-провайдеры не должны использовать tenant данные для обучения без отдельного явного договора и разрешения. |

Конкретные требования законодательства Казахстана и других стран должны оформляться отдельными legal profiles после юридического анализа; данный BRD не заменяет такой анализ.
