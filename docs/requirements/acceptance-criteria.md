## Общие критерии для каждой истории

1. Положительный, альтернативный, permission-denied, validation, concurrent update и retry сценарии покрыты тестами.
2. Изменение tenant-сущности аудируется согласно каталогу; PII не попадает в технические логи.
3. API и UI используют одинаковые бизнес-правила и коды ошибок.
4. Для асинхронного действия доступны статус, correlation ID, безопасный повтор и DLQ/runbook.
5. Метрики и события добавлены до признания истории готовой.
