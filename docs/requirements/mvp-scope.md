# Состав MVP

## 1. Принцип MVP

MVP подтверждает три сквозных сценария: (1) контакт → партнер → адаптация, (2) контакт → клиент → заказ → сопровождение → повторный заказ, (3) лидер → обзор ветки → выявление отклонения → задача наставнику.

## 2. Входит

| Epic | Состав | Приоритет |
|---|---|---|
| Identity/Tenant | регистрация по приглашению, вход, восстановление, tenant membership, RBAC/ABAC, профиль, MFA для привилегированных ролей | Must |
| Contacts | карточка, мультироли, теги, поиск, CSV import/export, дубли, merge, архив | Must |
| Recruiting | настраиваемая воронка, Kanban/list, переходы, причины отказа, задачи, журнал | Must |
| Sales | клиентская воронка, предложение, заказ, оплата/доставка как статусы | Must |
| Network | внутреннее дерево и CSV/API import, sponsor/mentor, поиск, базовые показатели | Must |
| Product | каталог, категории, цены, документы и правила использования | Must |
| Orders | ручной/повторный заказ, позиции, скидка, статусы, отмена/возврат, история | Must |
| Follow-up | шаблон по продукту/категории, экземпляр, касания, жалоба/эскалация | Must |
| Repeat sales | ожидаемое окончание, сегменты, задача, черновик повторного заказа | Must |
| Work management | задачи, чек-листы, календарное представление, напоминания | Must |
| Notifications | in-app и email, предпочтения, журнал доставки | Must |
| Content/Knowledge | утвержденная библиотека, категории, поиск, версии | Must |
| Analytics | персональная панель, базовые воронки, продажи, сопровождение, структура | Must |
| AI limited | резюме контакта, проект сообщения, план дня, поиск по базе знаний; подтверждение человеком | Should |
| Administration | справочники, этапы, обязательные поля, шаблоны, follow-up, права, импорт | Must |
| Audit | неизменяемый прикладной журнал значимых действий | Must |

## 3. Не входит в MVP

- полноценная LMS с экзаменами и сертификатами;
- расширенные мероприятия с QR-регистрацией;
- геймификация, марафоны и награды;
- нативные iOS/Android приложения и офлайн-режим;
- собственный платежный шлюз, WMS, ERP и расчет вознаграждений;
- сложный конструктор маркетингового плана и автоматический расчет рангов;
- автономные AI-действия и генерация изображений/видео;
- публикация во все социальные сети;
- полноценный клиентский портал и подписочная биллинговая платформа;
- прогнозные ML-модели до накопления качественных данных.

## 4. Критерии готовности MVP

| ID | Критерий |
|---|---|
| ACC-MVP-001 | Все три сквозных сценария выполняются в тестовом tenant без ручного изменения БД |
| ACC-MVP-002 | Нет известных дефектов уровня blocker/critical; high имеют согласованный workaround |
| ACC-MVP-003 | Автотестами покрыты авторизация, tenant isolation, заказы, переходы воронок и права |
| ACC-MVP-004 | Выполнены тесты изоляции данных между tenant и областями структуры |
| ACC-MVP-005 | Импорт имеет dry-run, отчет ошибок и повторный безопасный запуск |
| ACC-MVP-006 | Все изменения заказов, связей структуры, прав, согласий и AI-рекомендаций аудируются |
| ACC-MVP-007 | Метрики из аналитики сверены с контрольной выборкой |
| ACC-MVP-008 | Есть runbook резервного восстановления, интеграционных ошибок и отключения AI |
| ACC-MVP-009 | Администратор настраивает этапы и follow-up без изменения кода |
| ACC-MVP-010 | Документация API, модели данных и пользовательские инструкции актуальны релизу |

## 5. Зависимости и риски

- согласование модели владения контактами и области видимости;
- качество и доступность данных внешней компании;
- официальные разрешения провайдеров коммуникаций;
- утвержденные сведения о продукции и юридические предупреждения;
- решение о master-системе для заказов, цен, остатков и структуры;
- локальные требования к согласиям и хранению данных.

## 6. Рекомендуемая последовательность

1. Tenant, identity, permissions, audit и базовые справочники.
2. Contacts, activities, tasks и import/export.
3. Recruiting и network.
4. Product, sales и orders.
5. Follow-up и repeat sales.
6. Notifications, content/knowledge и dashboard.
7. Ограниченные AI-сценарии.
8. Интеграционные адаптеры, hardening и пилот.
